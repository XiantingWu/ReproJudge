# Code of Conduct

## Our standard

Project participation should be professional, technically focused, and respectful. Contributions are evaluated on evidence, reproducibility, security, and clarity rather than status or identity.

Unacceptable behavior includes harassment, threats, publication of private information, deliberate disruption, or knowingly submitting malicious code or credentials.

## Enforcement

### Private reporting route

Conduct concerns are reported **privately** through the repository's private reporting form (Settings → Security → Private vulnerability reporting, enabled at public launch). The form is GitHub's standard private channel and does not publish the report. Mark the report as a **conduct report** so it is handled separately from security vulnerabilities; the two report types are triaged by different response rules (see below).

Before private vulnerability reporting is available (while the repository is private), use GitHub's standard private contact channels — GitHub support or the platform's report-content flows — and reference this repository.

No conduct report should be posted in public issues, pull requests, or discussions. Do not publish details of an ongoing enforcement matter.

### Response rules

Security vulnerability reports (private reporting form, marked **security**) follow [SECURITY.md](SECURITY.md): fail-closed private handling, no public exploit details, patch/yank/advisory decisions made by the maintainer.

Conduct reports (private reporting form, marked **conduct**) are reviewed by the maintainer and handled privately. Enforcement may include editing, rejecting, or removing contributions and restricting participation when needed to protect contributors or the project.

This policy applies to repository discussions, pull requests, issues, code review, and project-controlled community spaces.
