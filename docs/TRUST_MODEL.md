# Trust model

## Inputs

| Input | Trust | Primary controls |
|---|---|---|
| task manifest | untrusted | regular-file/symlink checks, 1 MiB cap, strict finite JSON, field/path/count/serialized-size bounds |
| evaluator checks/gold | maintainer/task-author controlled | omitted from generated agent-visible request; source/task fingerprinted |
| agent argv | operator-controlled | no shell expansion, bounded argv, recorded verbatim |
| inherited environment | sensitive | disabled by default |
| agent stdout/stderr | untrusted | 8 MiB capture cap per stream |
| artifacts | untrusted | root confinement, every symlink component refused, scorer/hash byte caps, fail-closed provenance |
| regex patterns/text | task/artifact controlled | manifest/text caps plus isolated child evaluation with hard timeout |
| telemetry | untrusted | separate file, 64 KiB cap, strict key/type/finite-value bounds |
| result files during aggregation | untrusted historical data | symlink/root confinement, 4 MiB cap, finite/status-consistency checks, malformed data fails closed |
| release evidence | trusted only after gate promotion | version/source/task/suite/agent/result hash checks and explicit scope claims |

## Authority separation

Task authors declare evaluator checks. Agents receive a projected request and produce artifacts. Deterministic evaluator code applies private checks. Maintainers decide which task suites become release evidence.

The normal ReproJudge request protocol therefore does not directly hand the agent expected numeric values, JSON gold values, regexes, or expected hashes.

This is not equivalent to hidden-gold OS isolation. A hostile process-mode agent retains the caller's filesystem permissions and may search for benchmark source files if they are readable on the same host. Competitive hidden-gold evaluation must place the agent in a container/VM/worker that does not mount evaluator manifests or gold data.

## Host/runtime boundary

Application-level limits protect evaluator integrity but do not constrain all behavior of an arbitrary process. Process-mode agents retain the OS permissions of the caller.

On POSIX, the runner creates a new session. After the agent leader exits, ReproJudge terminates remaining descendants in that same process group before it scores or hashes artifacts; timeout cleanup escalates the group from TERM to KILL. A hostile child can deliberately create a new session and escape this application-level group, so OS/container/VM isolation remains required for hostile code.

For untrusted third-party or hostile agents, place the agent command inside an isolation boundary appropriate to the threat model. ReproJudge itself remains the evaluator/contract layer.

## Repository execution boundary

This repository intentionally uses **no GitHub Actions workflows**. All quality gates run locally under the maintainer's control. Personal workstations are the execution domain: no repository CI, release, or publish job executes on hosted runners because none exist by design.

Release evidence is generated by the standalone measurement process described in [EVIDENCE.md](EVIDENCE.md) and [RELEASING.md](RELEASING.md). Maintainer-controlled `main` commits are the only paths that can produce formal release evidence; no fork or automated change can reach the evidence or publication path because no workflow triggers exist.

No persistent or personal runner registration exists or is permitted for this repository.

### Public-log privacy boundary

No GitHub Actions logs are produced because no workflows exist. Local execution may still emit logs; credentials, tokens, secret-bearing argv, and secret environment values must never be printed.

## Environment credentials

Default process environment includes only a small portability allowlist plus `REPROJUDGE_*` paths/IDs. `--inherit-env` deliberately opts out of this protection.

Because argv is evidence, secret-bearing argv is prohibited by policy.

## Resource bounds

Captured logs, manifest/telemetry/result parsing, text/JSON scoring and artifact hashing all have explicit byte limits. A declared artifact that cannot be hash-evidenced within policy prevents `passed`; provenance is never silently dropped from an otherwise passing run.

These are evaluator-integrity limits, not kernel CPU/memory/PID quotas.

## Scientific trust

- file identity is not semantic validity;
- textual/regex match is not scientific equivalence;
- numeric tolerance is meaningful only if the task author chose a scientifically justified metric/tolerance;
- process success is not scientific success;
- public benchmark gold can be gamed unless the evaluation environment hides it;
- benchmark curation and evaluator mechanics are separate quality dimensions.
